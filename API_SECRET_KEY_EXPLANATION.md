# API_SECRET_KEY - Объяснение

## Что это?

`API_SECRET_KEY` - это **ваш собственный секретный ключ** для защиты HTTP API бота от несанкционированного доступа.

Это **НЕ ключ от Polymarket**, а просто пароль/токен, который вы придумываете сами для защиты endpoint `/bets/`.

## Зачем он нужен?

Когда парсер (на другом сервере) отправляет ставки на ваш бот через HTTP API, нужно убедиться, что запросы приходят именно от вашего парсера, а не от посторонних.

## Откуда брать?

**Вы придумываете этот ключ сами!** Это может быть любая случайная строка.

### Рекомендации:

1. **Длинный случайный ключ** (рекомендуется):
   ```bash
   # Генерация случайного ключа (Linux/Mac)
   openssl rand -hex 32
   
   # Или Python
   python3 -c "import secrets; print(secrets.token_urlsafe(32))"
   ```

2. **Простой пароль** (для тестирования):
   - Можно использовать что-то простое типа: `my_secret_key_123`
   - Но для продакшена лучше использовать длинный случайный ключ

### Примеры:

```env
# Простой вариант (для тестирования)
API_SECRET_KEY=my_bot_secret_key_12345

# Безопасный вариант (рекомендуется)
API_SECRET_KEY=a7f3b9c2d4e1f6g8h0i2j4k6l8m0n2p4q6r8s0t2u4v6w8x0y2z4
```

## Как используется?

### 1. В боте (приемник):

В `.env` файле бота:
```env
API_SECRET_KEY=your_secret_key_here
```

Бот проверяет этот ключ в заголовке `X-Secret-Key` каждого запроса.

### 2. В парсере (отправитель):

В `.env` файле парсера:
```env
POLYMARKET_BOT_SECRET_KEY=your_secret_key_here
```

Парсер отправляет этот ключ в заголовке `X-Secret-Key` при отправке ставок.

## Важно!

⚠️ **Один и тот же ключ должен быть:**
- В `.env` файле бота (`API_SECRET_KEY`)
- В `.env` файле парсера (`POLYMARKET_BOT_SECRET_KEY`)

Если ключи не совпадают, парсер не сможет отправлять ставки на бот (получит ошибку 401).

## Опциональность

Если `API_SECRET_KEY` не указан (или пустой), защита отключается и любой может отправлять запросы на бот.

**Для продакшена рекомендуется всегда использовать секретный ключ!**

## Пример настройки

### На сервере с ботом (`/root/polymarket_bot/.env`):

```env
API_SECRET_KEY=a7f3b9c2d4e1f6g8h0i2j4k6l8m0n2p4q6r8s0t2u4v6w8x0y2z4
```

### На сервере с парсером (в `.env` парсера):

```env
POLYMARKET_BOT_URL=http://YOUR_BOT_SERVER_IP:8000/bets
POLYMARKET_BOT_SECRET_KEY=a7f3b9c2d4e1f6g8h0i2j4k6l8m0n2p4q6r8s0t2u4v6w8x0y2z4
```

Обратите внимание: **один и тот же ключ в обоих местах!**

## Как проверить работу

### 1. Без ключа (если отключена защита):

```bash
curl -X POST http://localhost:8000/bets/ \
  -H "Content-Type: application/json" \
  -d '{"bookmaker": "POLYMARKET", ...}'
```

### 2. С ключом:

```bash
curl -X POST http://localhost:8000/bets/ \
  -H "Content-Type: application/json" \
  -H "X-Secret-Key: your_secret_key_here" \
  -d '{"bookmaker": "POLYMARKET", ...}'
```

### 3. С неправильным ключом (получите ошибку 401):

```bash
curl -X POST http://localhost:8000/bets/ \
  -H "Content-Type: application/json" \
  -H "X-Secret-Key: wrong_key" \
  -d '{"bookmaker": "POLYMARKET", ...}'
# Ответ: {"detail": "Invalid secret key"}
```
